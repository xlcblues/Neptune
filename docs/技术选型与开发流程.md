# Neptune 技术选型与开发流程

## 1. 产品定位

Neptune 是一款面向 Windows 桌面端的本地音乐播放器，目标体验对标 Apple Music：

- 本地音乐文件扫描与持久化索引，支持断网使用；
- 自动识别音乐风格/流派，允许联网查询、指纹识别与本地 AI 作为兜底；
- 苹果式高级感界面：毛玻璃材质、深色海洋主题、流畅弹性动效；
- 多种播放可视化特效（频谱、极光、波形、黑胶、粒子等）；
- 用户自建歌单与音乐库管理；
- 数据全部保存在本地，隐私可控。

## 2. 技术选型

### 2.1 桌面框架对比

| 方案 | 安装包/内存 | 原生窗口效果 | 音频与系统能力 | 前端生态 | 结论 |
| --- | --- | --- | --- | --- | --- |
| Electron | 大（150MB+）/ 内存高 | 依赖第三方实现 Mica/Acrylic | JS 生态成熟 | 最成熟 | 备选 |
| **Tauri 2（Rust + WebView2）** | 小（5-20MB）/ 内存低 | 原生 Mica/Acrylic/Transparent 支持好 | Rust 适合索引、指纹、数据库 | React 等全兼容 | **推荐** |
| WPF + .NET 8 | 原生、适中 | Windows 原生效果好 | NAudio/TagLib 成熟 | 动画开发成本高 | 备选 |
| Avalonia | 原生、适中 | 跨平台但 Windows 特效一般 | 生态较小 | 一般 | 备选 |
| Flutter Desktop | 原生、适中 | 渲染自绘，毛玻璃需自实现 | 音频/系统集成生态一般 | 动画强 | 备选 |

### 2.2 推荐技术栈

**桌面容器：Tauri 2 + Rust**

- 体积小、启动快，适合本地工具类软件；
- Rust 后端便于实现目录遍历、元数据解析、指纹计算、SQLite 索引与文件监控；
- Windows 11 下可调用原生 Mica/Acrylic 毛玻璃窗口效果，向苹果式视觉靠拢；
- 前端使用 WebView2（Windows 10/11 自带，缺失时可引导安装）。

**前端：React 18 + TypeScript + Vite**

- 组件化开发，适合音乐库、歌单、播放器等多视图应用；
- 动画使用 `motion`（Framer Motion）实现可打断的弹性动效；
- 状态管理使用 Zustand，音频播放状态与 UI 状态分离；
- 图标使用 `lucide-react`，风格统一且贴合系统级质感。

**样式与字体**

- 不使用重型 UI 框架，采用自研 Design Token + CSS 变量，便于精确控制苹果式高级感；
- 字体优先 `Segoe UI Variable Display` / `Segoe UI Variable`（Windows 11），回退 `Inter`、`Segoe UI`；
- 毛玻璃使用 `backdrop-filter: blur() + saturate()`，配合半透明材质与高光描边。

**音频引擎**

- 播放与可视化：`Web Audio API`，`AnalyserNode` 输出频谱数据；
- 解码：WebView2 支持 mp3 / flac / wav / ogg / m4a 常见格式；特殊格式由 Rust 侧车调用 FFmpeg 转码；
- 元数据解析：Rust `lofty` crate（ID3 / FLAC / MP4 / Vorbis 等标签）。

**本地索引与数据库**

- SQLite + FTS5（`rusqlite` 或 `sqlx`），负责曲库、歌单、分类结果与设置；
- 文件监控使用 Rust `notify` crate，实现增量扫描与实时入库；
- 封面与缩略图缓存使用本地目录 + 哈希文件名。

**智能分类（多级降级策略）**

1. 优先读取文件内 `Genre` 标签；
2. 指纹识别：Chromaprint / AcoustID，匹配 MusicBrainz 数据库，准确度高；
3. 联网元数据：MusicBrainz API 按 艺人+专辑 查询风格；
4. 本地 AI 兜底：Ollama（如 Qwen3 / Llama3）或 ONNX 轻量分类模型，基于标题、艺人、歌词与音频低层特征推断；
5. 用户可手动确认或修改，结果写回曲库并支持批量更新。

**播放特效**

- Canvas 2D / WebGL + AnalyserNode；
- 内置多套预设：频谱条、极光频谱、波形镜面、黑胶旋转、粒子声场、动态封面流光；
- 支持随音乐节奏切换与跟随封面主色染色。

## 3. 系统架构

```text
┌─────────────────────────── Frontend (React/WebView2) ───────────────────────────┐
│  Library UI │ Playlist UI │ Classify UI │ Player UI │ Visualizers (Canvas/WebGL) │
└──────────────────────────────────┬──────────────────────────────────────────────────┘
                                 │ Tauri IPC (commands / events)
┌──────────────────────────────────┴──────────────────────────────────────────────────┐
│                              Rust Core                                           │
│  Indexer │ Metadata │ SQLite+FTS │ File Watch │ Fingerprint │ Classifier │ Audio │
└─────────────────────────────────────────────────────────────────────────────────────┘
                               │
                   本地音乐目录 / 封面缓存 / 数据库文件
```

数据流：

1. 用户添加文件夹 → Rust Indexer 递归扫描，解析元数据 → 写入 SQLite；
2. 后台任务计算指纹/联网查询/本地 AI → 生成分类建议 → 写回曲库；
3. 前端通过 Tauri command 读取曲库，通过 event 接收扫描与分类进度；
4. 播放时前端用 Web Audio 解码播放，AnalyserNode 输出频谱给可视化层。

## 5. 数据模型

```sql
tracks          -- id, path(unique), title, artist, album, duration_ms, bitrate,
                 -- sample_rate, channels, cover_path, added_at, updated_at
track_genres    -- track_id, genre, confidence, source(metadata/fingerprint/network/ai/manual)
playlists       -- id, name, description, cover_path, created_at, updated_at
playlist_tracks -- playlist_id, track_id, position
scan_jobs       -- id, root, status, started_at, finished_at, total, found
settings        -- key, value（主题、音质、特效、默认目录等）
```

曲库表对 `title/artist/album` 建立 FTS5 索引，支持中文分词与模糊搜索。

## 6. 核心 Tauri 接口

| 接口 | 说明 |
| --- | --- |
| `add_folders(paths)` | 添加音乐目录并触发扫描 |
| `scan_progress`（event） | 扫描进度与结果推送 |
| `list_tracks(filter, sort, page)` | 分页/搜索/排序查询曲库 |
| `get_track(id)` | 获取单曲详情与封面 |
| `create_playlist(name)` | 新建歌单 |
| `add_to_playlist(id, track_ids)` | 批量加入歌单 |
| `remove_from_playlist(id, track_ids)` | 移除歌单内曲目 |
| `classify_track(id)` / `classify_batch(ids)` | 单曲/批量智能分类 |
| `apply_genre(track_id, genre)` | 用户确认或修改分类 |
| `update_metadata(id, fields)` | 编辑元数据并写回文件（可选） |
| `get_settings()` / `set_settings(patch)` | 设置读写 |
| `export_playlist(id, format)` | 导出歌单（m3u/txt/json） |

## 7. 开发流程与里程碑

### M0 脚手架与窗口质感（约 2 天）

- 初始化 Tauri 2 + React + Vite + TypeScript；
- 配置深色窗口、Mica/Acrylic 背景、圆角、无边框拖拽；
- 建立 Design Token、字体与毛玻璃基础组件；
- 完成 Logo 与品牌资源接入。

### M1 本地索引（约 5 天，已完成）

- Rust Indexer 递归扫描与增量扫描（notify）；
- lofty 元数据解析、封面提取；
- SQLite + FTS5 建表与查询；
- 前端音乐库列表、虚拟滚动、搜索排序；
- 单元测试与 1 万首样本库性能基准。

> 状态：2026-10-22 完成。`cargo test` 5 项通过，前端 `npm run build` 与浏览器 DOM 验收（搜索/排序/详情/窄屏）通过，Tauri 桌面端可启动并实时索引。

### M2 播放内核（约 4 天）

- 播放队列、播放/暂停/下一首/上一首/跳转/音量；
- Web Audio AnalyserNode 接入；
- 播放条（进度、时间、封面、控制按钮）；
- 快捷键（空格、方向键、媒体键）。

> 状态：2026-10-22 完成。`npm run build` 与 `cargo test`（5 项）通过；Playwright 验收覆盖播放/暂停、上一首/下一首、跳转、音量与静音、空格与方向键、队列切换、深浅主题窄屏布局，全部通过。验证截图见 `design/m2-player.png`、`design/m2-narrow-dark.png`、`design/m2-light.png`。

### M3 智能分类（约 6 天）

- 本地标签 → 指纹 → MusicBrainz → 本地 AI 多级降级管线；
- 分类结果展示、置信度、一键确认/批量应用；
- 断网降级与重试机制；
- 隐私说明：只上传指纹哈希，不上传音频文件。

### M4 歌单与库管理（约 4 天）

- 歌单 CRUD、拖拽排序、批量加入、导出；
- 曲目编辑与封面管理；
- 智能歌单（按流派/年代/时长自动生成）。

### M5 特效与打磨（约 5 天）

- 5+ 播放特效预设与设置面板；
- 过渡动效、空态/加载态/错误态；
- 深浅主题、无障碍（reduced motion / contrast）；
- 图标、安装包、签名与发布脚本（NSIS/MSIX）。

总周期：单人约 4-5 周；可并行推进 M1 与 M3 的调研。

## 8. 测试与质量

- Rust：`cargo test`，覆盖索引、元数据、数据库、指纹匹配；
- 前端：Vitest + Testing Library；
- E2E：Playwright 走查核心流程（添加目录 → 扫描 → 播放 → 建歌单）；
- 性能：10 万首级索引耗时、启动耗时、内存占用基准；
- 兼容：Windows 10/11、常见音频格式、中文/英文标签。

## 9. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 特殊音频格式不支持 | FFmpeg 侧车转码 |
| 联网分类失败/无网络 | 多级降级到本地标签与本地 AI |
| 指纹服务限流 | 批量任务队列 + 节流 + 缓存 |
| WebView2 缺失 | 首次启动检测并引导安装 |
| 大库扫描卡顿 | 增量扫描、线程池、虚拟滚动 |
| 版权与隐私顾虑 | 不传播音频，仅本地播放；指纹只传哈希 |
